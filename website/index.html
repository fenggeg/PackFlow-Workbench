Why PackFlow

从项目解析到打包完成，不再在终端之间反复切换。

多模块项目的痛点不只是打包——环境配置、模块选择、命令编排、构建诊断、产物定位散落在不同工具里。PackFlow 把它们放到同一个操作闭环中。

Build Center

构建命令可视化编排

自动解析 Maven 多模块结构，集中管理 JDK、Maven、Profile 和常用参数，执行前可预览并微调最终命令，构建失败自动诊断原因。

Artifact Manager

构建产物一站式管理

聚合所有模块的构建产物，按模块和规则筛选目标文件，支持打开文件夹、复制路径和删除产物。

Dependency Analysis

依赖图与冲突检测

自动分析模块间依赖关系，检测依赖冲突并生成排除代码，避免版本不一致导致的构建问题。

Git Integration

Git 状态与分支管理

查看 Git 状态、拉取远程更新、切换分支，构建前确认代码版本，无需额外 Git 客户端。

Build History

构建历史与模板

构建记录统一查看，支持重跑和删除；常用构建参数保存为模板，一键复用。

Windows Native

为本地桌面场景打磨

基于 Tauri 2 与 Rust 后端，结合 SQLite 持久化、Job Objects 进程管理和自动更新，贴近 Windows 开发习惯。

FAQ

安装前最关键的问题。

它是 Web 系统还是桌面应用？

它是面向 Windows 的本地桌面应用，用来管理本地 Maven 项目的构建和产物。

支持多模块项目吗？

支持。自动解析 Maven 父工程的多模块结构，以模块树展示，可勾选部分模块构建并自动处理模块间依赖。

构建失败怎么办？

内置诊断引擎，构建失败后自动分析日志，定位常见原因并给出修复建议，无需翻阅完整日志。

能检测依赖冲突吗？

可以。自动分析模块依赖关系，检测版本冲突并生成排除代码，支持单个和批量排除。

数据存在哪里？

项目、构建历史和模板保存在应用数据目录中的 SQLite 数据库，按项目隔离。

需要预装 Java 或 Maven 吗？

应用会自动检测系统中的 JDK 和 Maven 环境，也支持手动注册 JDK 和配置多套环境方案按项目绑定。
